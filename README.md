# Электронное QR-меню — Фуджи Суши Friends

Гость сканирует QR на столе → входит по номеру телефона или через приложение Фуджи → подбирает блюда с AI или в меню → передаёт заказ официанту → официант подтверждает и отправляет в iiko на стол → дозаказ → счёт → оплата с чаевыми → оценка визита.

Дизайн гостевого меню — по макету Figma «WEB MENU».

## Быстрый старт (локально)

```bash
# 1. PostgreSQL
docker run -d --name menu-postgres -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:17-alpine

# 2. API + фронт (одним процессом)
cd menu-api
cp .env.example .env          # впишите IIKO_API_LOGIN и OPENROUTER_API_KEY
npm install
npm run db:migrate            # схема, 7 ресторанов, AI-чипы, пользователи персонала (идемпотентно)
npm run db:sync               # меню из iiko (если есть ключ)
npm run db:demo               # демо-меню только для ресторанов без выгрузки (для показа офлайн)
npm start
```

| Адрес | Что это |
|---|---|
| http://localhost:3101/?table=5 | Гость, стол 5, ресторан по умолчанию (`QR_RESTAURANT_SLUG`) |
| http://localhost:3101/?restaurant=leningradskaya&table=5 | Гость, конкретный ресторан |
| http://localhost:3101/staff/ | Терминал персонала |

Пользователи по умолчанию (пароли задаются в `.env` при первом `db:migrate`, потом меняются в админке):

| Логин | Пароль | Роль |
|---|---|---|
| `waiter` | `1111` | Официант: уведомления, столы, правка заказа, «В работу» → iiko |
| `manager` | `manager` | Управляющий: + контроль зала, отзывы |
| `admin` | `admin` | Администратор: + меню/стоп-лист, AI-подсказки, акции, QR-коды, сотрудники, журнал |

Сквозной тест всего сценария (сервер должен быть запущен): `npm run test:e2e`.

## Стол, гости, кухня

- **QR** сразу выбирает ресторан и стол. Сменить ресторан можно вручную: нажать на название ресторана в шапке.
- **Первый гость** вводит телефон и имя, и для стола открывается визит.
- **Если за столом уже есть гости или заказ,** следующий гость видит «Стол №N уже занят. За столом: Анна» и присоединяется под своим именем. Число гостей в заказе растёт, каждый гость получает своё место (1, 2, …).
- **Корзина у каждого гостя своя.** Блюда отмечены именем и местом. Остальные гости видят блок «За столом» со статусами блюд.
- **Официант** сначала подтверждает заказ и только потом нажимает «В работу». Позиции уходят в iiko (`order/create` / `order/add_items`) по порядку курсов, у каждой комментарий «Анна, место 1, курс 2».
- **Статусы кухни** приходят вебхуком `TableOrderUpdate` плюс опросом раз в 20 с (`KITCHEN_POLL_MS`). Когда блюдо становится «Готово», официанту приходит уведомление «Стол №N — готово, пора выносить» со звуком. В терминале есть кнопка «Вынесено».
- **Без ключа iiko** (демо-режим) кухня имитируется по времени (`IIKO_DEMO_COOK_SEC`, 45 с).

## Как работает AI

- Модели (OpenRouter, по умолчанию `openai/gpt-4o-mini`) передаётся **всё доступное меню ресторана**: название, категория, цена, вес, КБЖУ, аллергены, **состав/ингредиенты**, метка «рекомендуем». Позиции из стоп-листа не передаются.
- Вместе с меню передаются запрос гостя (текст или чип), имя, аллергии, что гость заказывал раньше и что уже лежит в корзине.
- Модель отвечает коротким сообщением и списком блюд строго из меню с объяснением «почему». Номера, которых нет в меню, отбрасываются. Аллергены дополнительно фильтруются на сервере.
- Меню стоит в начале промпта в стабильном порядке — провайдер кэширует его, ответ быстрее.
- Если OpenRouter не ответил за `AI_LLM_TIMEOUT_MS` (4,5 с), сразу срабатывает мгновенный подбор по ключевым словам и популярности. Пустого экрана не бывает.
- Чипы редактируются в админке (`AI-подсказки`), «Рекомендуем» у блюда поднимает его в выдаче.

## Меню

Схема: **выгрузили меню из iiko → правим карточки в админке → заказ уходит в iiko по ID блюда.**

- **Источник** — внешнее меню iiko (`/api/2/menu` → `/api/2/menu/by_id`, один запрос на все рестораны, цены — по организации ресторана). Меню выбирается так: `IIKO_EXTERNAL_MENU_ID` (ID напрямую) → `IIKO_EXTERNAL_MENU` (часть названия) → «ресторан/зал/qr» в названии → единственное меню ключа. Один API-логин iiko на меню и заказы. Номенклатура iiko используется, только если внешнее меню не подключено. Сайт и приложение Фуджи не используются.
- **Хранение**: меню лежит на сервере (БД + память) и отдаётся за миллисекунды. Полная перевыгрузка — **раз в сутки** (`IIKO_SYNC_MS`); при старте — только если выгрузка устарела или у ресторана пустое меню; вручную — кнопка «Перевыгрузить из iiko» в админке.
- **Карточки блюд**: фото (загрузка файлом или ссылкой), название, описание, вес, КБЖУ, аллергены, «рекомендуем». Правятся в админке и накладываются по **UUID блюда в iiko**; в iiko ничего не записывается, перевыгрузка правки не затирает. Кнопка «Вернуть как в iiko» убирает правки.
- **Стоп-лист**: вебхук iiko `StopListUpdate` → `POST /api/v1/iiko/webhook` (заголовок `Authorization` = `IIKO_WEBHOOK_TOKEN`). Сервер сам регистрирует вебхук у организаций, если у ключа ещё не указан другой адрес (чужие настройки не трогает). Страховочная сверка — раз в 10 минут, одним запросом. Плюс ручной стоп в админке. Позиция видна, но недоступна.
- **Статус кухни**: вебхук `TableOrderUpdate` + опрос раз в минуту.

## iiko

- «В работу» у официанта: `order/create` на стол (`tableIds`, число гостей) или `order/add_items` для дозаказа. Отправляются только новые позиции, без дублей.
- Стол ищется по номеру в схеме зала (`reserve/available_restaurant_sections`) и кэшируется.
- При ошибке iiko официант видит причину, корзина сохраняется, отправку можно повторить.
- Без `IIKO_API_LOGIN` (или с `IIKO_DEMO=true`) работает демо-режим: номер заказа генерируется локально.
- После онлайн-оплаты счёт закрывается в iiko, если задан `IIKO_PAYMENT_TYPE_ID`, иначе официант получает уведомление закрыть счёт.

## Что в прототипе условно

- **Оплата** — демо-провайдер (успешна сразу). Точка подключения реального провайдера — `payBill()` в `services/table-session.js`. Защита от двойной оплаты уже есть (уникальный индекс + блокировка строки).
- **Вход через приложение Fuji** — принимается `?fujiToken=<JWT основного API>`. Токен проверяется через `GET /api/v1/user/:phone` prod API или локально по `FUJI_JWT_SECRET`. Кнопке «Войти через приложение Фуджи» нужен deep link (`FUJI_APP_LOGIN_URL`) от команды приложения.
- **Уведомления персонала** — лента в терминале со звуком (опрос раз в 5 с). Telegram для управляющего — по решению заказчика.

## Деплой через GitHub Actions

Workflow `.github/workflows/deploy.yml` выкатывает прод на `menu.franchise-fuji.ru` при каждом push в `main`; вручную — **Actions → Deploy → Run workflow** (можно выбрать ветку). Он заходит на сервер по SSH и запускает `deploy/update.sh`:

1. подтягивает код ветки, `npm ci`;
2. дописывает в `menu-api/.env` недостающие настройки (секрет подписи, ключи из GitHub Secrets, пароли персонала). Уже заданные значения сохраняются;
3. `db/migrate.js` — идемпотентная миграция, старые данные сохраняются; выгрузка меню из iiko;
4. перезапускает сервис `menu-api` и обновляет nginx (с бэкапом и откатом, если конфиг не прошёл `nginx -t`);
5. проверяет `/health` и меню.

**Секреты** (Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Обязателен | Что это |
|---|---|---|
| `DEPLOY_HOST` | да | IP сервера (`37.139.43.117`) |
| `DEPLOY_USER` | да | пользователь SSH (`ubuntu`) |
| `DEPLOY_SSH_KEY` | да | приватный SSH-ключ, публичная часть — в `~/.ssh/authorized_keys` на сервере |
| `OPENROUTER_API_KEY` | да | ключ AI |
| `IIKO_API_LOGIN` | да | API-логин iiko «электронное меню» — один ключ на всё: меню, заказы в стол, стоп-лист, статусы кухни, вебхук (можно назвать и `IIKO_MENU_API_LOGIN`) |
| `IIKO_CLIENT_SECRET` | для новых ключей | секрет клиента этого ключа (можно назвать и `IIKO_MENU_CLIENT_SECRET`) |
| `IIKO_EXTERNAL_MENU_ID` | нет | ID внешнего меню iiko — брать его напрямую |
| `ADMIN_PASSWORD`, `MANAGER_PASSWORD`, `WAITER_PASSWORD` | нет | пароли персонала при первом деплое. Без них генерируются случайные и хранятся только в `.env` на сервере |

Первичная установка на чистый сервер — `deploy/server-setup.sh`. Nginx проксирует всё на `menu-api`, а `/uploads`, `/_ipx`, `/content` (фото блюд) — на prod API Фуджи.
