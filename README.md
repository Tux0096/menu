# Электронное QR-меню — Фуджи Суши Friends

Гость сканирует QR на столе → входит по номеру телефона или через приложение Фуджи → подбирает блюда с AI или в меню → передаёт заказ официанту → официант подтверждает и отправляет в iiko на стол → дозаказ → счёт → оплата с чаевыми → оценка визита.

Дизайн гостевого меню — по макету Figma «WEB MENU».

## Быстрый старт (локально)

```bash
# 1. PostgreSQL
docker run -d --name menu-postgres -e POSTGRES_PASSWORD=postgres -p 5432:5432 postgres:17-alpine

# 2. API + фронт (одним процессом)
cd menu-api
cp .env.example .env          # впишите IIKO_API_LOGIN и OPENROUTER_API_KEY
npm install
npm run db:migrate            # схема, 7 ресторанов, AI-чипы, пользователи персонала (идемпотентно)
npm run db:sync               # меню из iiko (если есть ключ)
npm run db:demo               # демо-меню только для ресторанов без выгрузки (для показа офлайн)
npm start
```

| Адрес | Что это |
|---|---|
| http://localhost:3101/?table=5 | Гость, стол 5, ресторан по умолчанию (`QR_RESTAURANT_SLUG`) |
| http://localhost:3101/?restaurant=leningradskaya&table=5 | Гость, конкретный ресторан |
| http://localhost:3101/staff/ | Терминал персонала |

Пользователи по умолчанию (пароли задаются в `.env` при первом `db:migrate`, потом меняются в админке):

| Логин | Пароль | Роль |
|---|---|---|
| `waiter` | `1111` | Официант: уведомления, столы, правка заказа, «В работу» → iiko |
| `manager` | `manager` | Управляющий: + контроль зала, отзывы |
| `admin` | `admin` | Администратор: + меню/стоп-лист, AI-подсказки, акции, QR-коды, сотрудники, журнал |

Сквозной тест всего сценария (сервер должен быть запущен): `npm run test:e2e`.

## Как работает AI

- Модели (OpenRouter, по умолчанию `openai/gpt-4o-mini`) передаётся **всё доступное меню ресторана**: название, категория, цена, вес, КБЖУ, аллергены, **состав/ингредиенты**, метка «рекомендуем». Позиции из стоп-листа не передаются.
- Вместе с меню передаются запрос гостя (текст или чип), имя, аллергии, что гость заказывал раньше и что уже лежит в корзине.
- Модель отвечает коротким сообщением и списком блюд строго из меню с объяснением «почему». Номера, которых нет в меню, отбрасываются. Аллергены дополнительно фильтруются на сервере.
- Меню стоит в начале промпта в стабильном порядке — провайдер кэширует его, ответ быстрее.
- Если OpenRouter не ответил за `AI_LLM_TIMEOUT_MS` (4,5 с), сразу срабатывает мгновенный подбор по ключевым словам и популярности. Пустого экрана не бывает.
- Чипы редактируются в админке (`AI-подсказки`), «Рекомендуем» у блюда поднимает его в выдаче.

## Меню

1. `GET /api/v1/restaurants/:slug/catalog` берёт полное меню с фото и КБЖУ из prod API Фуджи (`LEGACY_API_URL`).
2. Если prod API недоступен — товары из iiko (`npm run db:sync`).
3. Если и это недоступно — последний успешный снимок (`catalog_snapshots`), меню не пропадает.
4. Поверх накладываются правки админки (стоп-лист, скрытие, фото, описание, КБЖУ, аллергены — для ресторана или всей сети) и стоп-лист iiko (`/api/1/stop_lists`). Позиции из стоп-листа видны, но недоступны для заказа.

## iiko

- «В работу» у официанта: `order/create` на стол (`tableIds`, число гостей) или `order/add_items` для дозаказа. Отправляются только новые позиции, без дублей.
- Стол ищется по номеру в схеме зала (`reserve/available_restaurant_sections`) и кэшируется.
- При ошибке iiko официант видит причину, корзина сохраняется, отправку можно повторить.
- Без `IIKO_API_LOGIN` (или с `IIKO_DEMO=true`) работает демо-режим: номер заказа генерируется локально.
- После онлайн-оплаты счёт закрывается в iiko, если задан `IIKO_PAYMENT_TYPE_ID`, иначе официант получает уведомление закрыть счёт.

## Что в прототипе условно

- **Оплата** — демо-провайдер (успешна сразу). Точка подключения реального провайдера — `payBill()` в `services/table-session.js`. Защита от двойной оплаты уже есть (уникальный индекс + блокировка строки).
- **Вход через приложение Fuji** — принимается `?fujiToken=<JWT основного API>`. Токен проверяется через `GET /api/v1/user/:phone` prod API или локально по `FUJI_JWT_SECRET`. Кнопке «Войти через приложение Фуджи» нужен deep link (`FUJI_APP_LOGIN_URL`) от команды приложения.
- **Уведомления персонала** — лента в терминале со звуком (опрос раз в 5 с). Telegram для управляющего — по решению заказчика.

## Деплой

`deploy/server-setup.sh` ставит Node, PostgreSQL (Docker), запускает миграцию, выгрузку iiko, systemd-сервис и nginx. Nginx проксирует всё на `menu-api`, а `/uploads`, `/_ipx`, `/content` (фото блюд) — на prod API Фуджи.
